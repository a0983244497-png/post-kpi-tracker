# 學員進度追蹤規格 — 課後小測驗 ＋ 每週打卡 ＋ 後台三清單（給夥伴）

> 專案：post-kpi-tracker（**Node.js / Express ＋ PostgreSQL / Railway**）
> 檔案：`db.js`（建表）、`routes/course.js`（API）、`lib/courseAccess.js`（權限）、`public/course-reader.html`（閱讀器）、`public/course.html`（學員課程首頁）、`public/course-admin.html`（後台）
> 目標：講師不用逐一私訊問進度，就能看到「誰卡住、誰消失、誰在進步」。
> 狀態：**草案，待 Gino 拍板第八節的待決定事項後才開始實作。**

---

## 一、設計原則（已討論過）

1. **追蹤藏在學員本來就想做的事裡**：看完課做 3 題小測驗（學員想知道自己懂了沒）、每週打卡（10 秒按完）。不另外要學員寫心得、填表、回報。
2. **學員不需另外註冊**：沿用現有課程帳號（email ＋ TV 名稱登入），所有紀錄都掛在 `pdf_students.id` 下。
3. **講師只看三個清單**：卡住的人、消失的人、進步的人。清單**即時從原始紀錄推算，不另存結果**（同「權限不另存死資料」的做法）。
4. **進步的學員經本人同意**才可作為案例素材；同意與否由後台手動記錄。
5. 目前人數（約 20～100 人）**不做自動推播／Email 提醒**，清單由講師自己看、自己決定要不要私訊。

## 二、對應現有架構（先讀懂現在有什麼）

| 現有東西 | 位置 | 這次怎麼用 |
|---|---|---|
| 學員表 `pdf_students`（id、email、name、tv_name、status、入金／等級欄位…） | `db.js` | 所有新紀錄都用 `student_id` 指向它；停用（`status='disabled'`）的學員不進三清單 |
| 課程單篇 `pdf_pdfs`（title、series_id、episode_no） | `db.js` | 測驗題目掛在每一篇 PDF 下 |
| 系列 `pdf_series`（新手篇→基礎→交易心理→進階） | `db.js` | 後台清單顯示「卡在哪個系列第幾篇」 |
| 分級權限 `tiers` / `tier_series` ＋ `lib/courseAccess.js` | 已上線 | 決定「**能看哪些系列**」；測驗解鎖若採用，只能在這個範圍內再加限制（見第四節） |
| 看完紀錄 `pdf_progress`（捲到最後一頁才記） | 已上線 | 當作「活動」訊號之一；測驗在學員捲到底、記為看完之後出現 |
| 閱讀器 `course-reader.html`（上一篇／下一篇、看完偵測） | 已上線 | 在最後一頁下方、「下一篇」按鈕上方插入測驗區 |
| 課程首頁 `course.html`（系列分組＋進度條） | 已上線 | 最上方加「本週打卡」卡片 |
| 後台 `course-admin.html`（名單匯入、入金、等級、學員列表、PDF 管理、權限開通） | 已上線 | 最上方新增「📊 學員追蹤」區塊；PDF 管理每列加「編輯題目」 |

> 現況缺口：目前**沒有記錄學員最後登入／最後開啟課程的時間**，`pdf_progress` 只在第一次看完時寫入（看完過的篇重看不會再記）。所以要判斷「消失」，需要補一個「最後出現時間」欄位（見第三節 `last_seen_at`）。

## 三、資料模型（PostgreSQL，全部用 `CREATE TABLE IF NOT EXISTS`／`ADD COLUMN IF NOT EXISTS` 寫在 `db.js`）

### 1. `pdf_quiz_questions`：每篇課程的題目
| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | SERIAL PK | |
| `pdf_id` | INTEGER → `pdf_pdfs(id)` ON DELETE CASCADE | 屬於哪一篇 |
| `sort_order` | INTEGER | 第幾題（1～3） |
| `question` | TEXT | 題目 |
| `options` | JSONB | 選項陣列，例如 `["A…","B…","C…"]`（建議一律 3～4 選 1） |
| `correct_index` | INTEGER | 正確選項的位置（從 0 開始） |
| `explanation` | TEXT | 答完後顯示的解釋（對錯都顯示） |
| `is_active` | BOOLEAN DEFAULT true | 題目改版時舊題停用、不刪，保留歷史作答 |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

### 2. `pdf_quiz_answers`：作答紀錄（**每答一次就新增一列，不覆蓋**）
| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | SERIAL PK | |
| `student_id` | INTEGER → `pdf_students(id)` ON DELETE CASCADE | 學員 |
| `pdf_id` | INTEGER → `pdf_pdfs(id)` ON DELETE CASCADE | 課程（冗餘存一份，查清單比較快） |
| `question_id` | INTEGER → `pdf_quiz_questions(id)` ON DELETE CASCADE | 題目 |
| `chosen_index` | INTEGER | 選了哪個 |
| `is_correct` | BOOLEAN | 對錯（由伺服器判斷，不信任前端） |
| `answered_at` | TIMESTAMPTZ DEFAULT NOW() | 時間 |

索引：`(student_id, answered_at)`、`(question_id, student_id)`。

> 為什麼不覆蓋：「卡住」要算「同一題錯幾次」，「進步」要比較前後答對率，都需要完整歷史。

### 3. `pdf_checkins`：每週打卡
| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | SERIAL PK | |
| `student_id` | INTEGER → `pdf_students(id)` ON DELETE CASCADE | |
| `week_start` | DATE | 該週週一（以台灣時間計） |
| `followed_plan` | VARCHAR(10) | `yes`＝有照計畫做單、`no`＝沒有照計畫、`no_trade`＝這週沒做單 |
| `mood` | SMALLINT CHECK 1–5 | 心情分數（1 很差 → 5 很好） |
| `created_at` / `updated_at` | TIMESTAMPTZ | |
| UNIQUE | `(student_id, week_start)` | 一週一筆；同週再按＝修改 |

### 4. `pdf_students` 新增欄位
- `last_seen_at` TIMESTAMPTZ NULL — 學員最後一次登入或開啟課程的時間（登入、`/my-pdfs`、開啟 PDF 時更新；同一小時內不重複寫，避免多餘寫入）。
- `case_consent` VARCHAR(10) DEFAULT 'none' — 案例素材同意狀態：`none` 未詢問／`asked` 已詢問／`agreed` 同意／`declined` 不同意。**由講師在後台手動標記**（實際詢問透過 LINE 等原本的管道）。

> 三個清單**不建表**，全部由上面的紀錄即時推算（學員 100 人以內，即時查詢沒有效能問題）。

## 四、課後小測驗

### 學員端流程（`course-reader.html`）
1. 學員捲到最後一頁 → 照現在的邏輯記為「已看完」。
2. 最後一頁下方出現「✏️ 小測驗（3 題）」區塊。該篇沒有題目就不出現。
3. 一題一題作答（或三題同頁），**按下選項立即顯示對／錯＋解釋**，不用等全部答完。
4. 答錯可以「再試一次」，每次重答都記一筆（這就是「卡住」的來源）。
5. 三題都答過後顯示小結：「3 題答對 2 題」，附「下一篇 →」按鈕。
6. 已作答過的篇再打開：顯示上次結果，可選擇「重新作答」。

### 權限關係：是否「答對才解鎖下一篇」（**待 Gino 決定**）

兩件事分開看：
- **依入金分級開通（已上線）**＝決定「你**能**看哪些系列」，是天花板。
- **測驗解鎖（新）**＝決定「在你能看的範圍內，**依什麼順序**看」。

不論選哪個方案，**測驗解鎖永遠不會開出入金等級以外的內容**；入金不夠的系列，測驗全對也看不到。

| 方案 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| **A. 不鎖（建議先上這個）** | 測驗只是回饋，下一篇照常開 | 不打斷學習、不會有人因為一題卡死而放棄；資料一樣收得到 | 有人會跳過測驗 |
| B. 軟提醒 | 沒答完／沒全對時，點「下一篇」跳提示「建議先完成測驗」，但可以繼續 | 有引導又不強迫 | 仍可跳過 |
| C. 硬鎖 | 上一篇 3 題全答對（可重試）才開下一篇 | 確保順序學習 | 實作較多；學員卡住會直接停掉；需處理下面的邊界情況 |

若選 C，需要一起決定的邊界：
- **跨系列**：入金升級後新開的系列第 1 篇，要不要求先過前一系列最後一篇的測驗？（建議：不要求，系列之間不互鎖）
- **手動覆蓋學員**（`is_override=true`，例如講師本人、招待帳號）：建議不受測驗鎖。
- **沒有題目的篇**：視為已通過。
- **舊學員**：上線前已看完的篇，要不要補做才能往下？（建議：已有 `pdf_progress` 看完紀錄的篇視為通過）
- 實作上鎖要寫在伺服器（`lib/courseAccess.js` 另加一個判斷，`/pdf/:id/file` 一起檢查），不能只在前端把按鈕藏起來。

### 後台出題（`course-admin.html` → PDF 管理）
- 每篇 PDF 一列多一個「編輯題目（0/3）」按鈕 → 彈窗編輯 3 題：題目、選項、正確答案、解釋。
- 修改已有人作答的題目時：只改錯字可直接存；改了題意或答案 → 舊題設 `is_active=false`、新增新題（避免舊作答紀錄對錯失真）。

## 五、每週打卡

### 學員端（`course.html` 最上方）
```
┌───────────────────────────────────────────┐
│ 本週打卡（10/20–10/26）                       │
│ 這週有照計畫做單嗎？                            │
│ [ 有 ]  [ 沒有 ]  [ 這週沒做單 ]               │
│ 這週心情：😣 1  2  3  4  5 😄                  │
│                              [ 送出 ]        │
└───────────────────────────────────────────┘
```
- **只有一題＋心情分數，不需要打字。**
- 本週已打卡 → 卡片縮成一行「✓ 本週已打卡（有照計畫・心情 4）　修改」。
- 週一 00:00（台灣時間）換週，上週沒打就算缺，不補打（是否允許補打列為待決定）。
- 可選加碼：卡片旁顯示「已連續打卡 N 週」，給學員一點成就感。

## 六、後台三個清單（`course-admin.html` 最上方新增「📊 學員追蹤」）

三個分頁或三張卡片並排，每張顯示人數；點開是名單。全部**即時推算**，只看 `status='active'` 的學員。

### 1. 🟥 卡住的人
**規則（草案）**：近 14 天內，某一題**答錯 ≥ 2 次，而且之後還沒答對過**。

| 學員 | 卡在哪 | 題目 | 錯幾次 | 最後作答 |
|---|---|---|---|---|
| 王小明 | 基礎系列｜第 3 篇 | 「停損應該放在…」 | 3 | 2 天前 |

- 一位學員卡多題時合併成一列，展開看全部。
- 附「全班最常錯的題」前 5 名 —— 這比較像是**題目或課程本身需要補充**的訊號，不一定是學員的問題。
- 後來答對了 → 自動從清單消失。

### 2. ⬜ 消失的人
**規則（草案）**：**連續 7 天沒有任何活動**。
活動＝以下任一個時間的最大值：`last_seen_at`（登入／開課程）、`pdf_progress.completed_at`、`pdf_quiz_answers.answered_at`、`pdf_checkins.created_at`。

| 學員 | 目前等級 | 最後活動 | 最後在做什麼 | 已消失 |
|---|---|---|---|---|
| 陳大華 | 心理 | 10/08 | 看完 交易心理系列｜第 2 篇 | 12 天 |

- 依「已消失天數」由多到少排序。
- 剛建檔、從來沒登入過的學員另外標「尚未開始」，不跟「上過課後消失」混在一起。
- 已看完所有可看內容的學員，標「已看完全部」作為參考（可能只是沒新內容，不一定是流失）。

### 3. 🟩 進步的人
**規則（草案，最需要 Gino 確認）**：比較「最近 4 週」和「再之前 4 週」，符合任一項就列入：
- **測驗**：第一次作答答對率提升 ≥ 20 個百分點（兩段期間各至少作答 6 題，避免樣本太少）。
- **打卡**：從「沒有照計畫」轉為**連續 3 週「有照計畫」**。
- （參考，不單獨列入）心情平均提升 ≥ 1 分。

| 學員 | 進步在哪 | 前 4 週 → 近 4 週 | 案例同意 |
|---|---|---|---|
| 林小美 | 照計畫做單 | 1/4 週 → 4/4 週 | 未詢問 [標記] |

- 「案例同意」欄可直接切換：未詢問 → 已詢問 → 同意／不同意（寫入 `case_consent`）。
- 只有標為「同意」的人才算可用案例；清單可篩選「只看已同意」。

### 單一學員追蹤明細（點名字展開）
- 測驗：各篇答對率、錯過的題目。
- 打卡：最近 8 週的照計畫／心情小圖（一格一週）。
- 最後活動時間。
（學員列表既有的「學習進度」欄保留不動。）

## 七、API 端點（掛在 `routes/course.js`，前綴 `/api/course`）

學員端（`requireStudent`）：
- `GET  /quiz/:pdfId` — 取該篇題目（**不含正確答案**）＋本人最近一次作答結果
- `POST /quiz/:pdfId/answer` — `{ question_id, chosen_index }` → 伺服器判對錯、寫一筆 `pdf_quiz_answers`，回傳 `{ is_correct, correct_index, explanation }`；需先確認學員有權看這篇（沿用 `listAccessiblePdfs`）
- `GET  /checkin/current` — 本週是否已打卡、內容、連續週數
- `PUT  /checkin/current` — `{ followed_plan, mood }` 新增或修改本週打卡

後台（`requireManager`）：
- `GET  /admin/pdfs/:id/quiz`、`PUT /admin/pdfs/:id/quiz` — 讀／存某篇的題目
- `GET  /admin/tracking/stuck` — 卡住清單（含全班最常錯題）
- `GET  /admin/tracking/inactive` — 消失清單
- `GET  /admin/tracking/improving` — 進步清單
- `GET  /admin/tracking/students/:id` — 單一學員明細
- `PATCH /admin/students/:id/case-consent` — `{ case_consent }`

修改既有：
- `POST /login`、`GET /my-pdfs`、`GET /pdf/:id/file` 順手更新 `last_seen_at`（一小時內不重寫）。
- 若第四節選方案 C：`lib/courseAccess.js` 加測驗解鎖判斷，`/my-pdfs` 回傳每篇 `locked`，`/pdf/:id/file` 擋未解鎖的篇。

| 13 | 手動覆蓋（講師、招待）帳號要不要從三清單排除？ | 排除／保留 | 排除講師本人，招待帳號保留 |

## 九、上線注意

- 先上資料表＋出題後台，**題目出好之後**再打開學員端測驗區（沒有題目的篇不顯示，不會壞）。
- `last_seen_at` 剛上線時所有人都是空的 → 頭 7 天「消失」清單會不準，用 `pdf_progress` 補算；或上線一週後才開消失清單。
- 進步清單需要累積 8 週資料才有意義，上線初期顯示「資料累積中」。
- 時區一律以台灣時間（Asia/Taipei）切週、算天數。

## 十、驗收標準

- [ ] 後台幫某篇存 3 題 → 學員捲到該篇最後一頁 → 出現 3 題測驗
